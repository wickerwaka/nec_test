## §1 TWO CORRECTIONS TO THE COMMISSIONING BRIEF, STATED BEFORE ANY NUMBER

**(a) `sw/fz2_a1_rescore.py` IS STRUCTURALLY BLIND TO THE WHOLE `C1` FAMILY,
AND SO IS EVERY FIGURE IT HAS EVER PRINTED ABOUT IT.**  Its `cut()` ends the
comparison at the chip's first `MEMR` T1 at linear `0x00008`/`0x0000A` at or
after the terminating NMI's assertion — the read the RIG SUBSTITUTES out of
its `TVEC` register.  **On 19 of the 20 scoreable `C1` seats the missed trap
happens AFTER that read**, because the trap the ucore drops is the one that
follows *the terminating NMI's own entry*.  MEASURED on `fz2c/400007`: the A1
window is **3,346** rows, the seed's banked window is **3,736**, the whole
divergence is at **3,378**, and A1 scores the seat `bad = 0` before and after
any change whatsoever.  A landing scored only on A1 would have reported
"0 gained, 0 lost" and meant nothing.

**(b) THE §38.9 POPULATION OF 40 IS NOT ONE MECHANISM.**  Read on the banked
rows (§2), it is **two**, and they are separated by a predicate that is
measured, not argued: *does an EXTERNAL interrupt entry sit between the last
matched instruction boundary and the vector-1 read the chip takes and the
core does not?*  19 scoreable seats say yes (all of them the terminating
NMI); 9 scoreable seats say no, and on **8 of those 9 the instruction after
the missed trap is `HLT` (`0xF4`) and the instruction before it is an
`IRET`**.  This pre-registration takes the first mechanism and **registers
the second as a NON-CLOSER with its own bar**.  Forcing them into one law
would be the fitted rule the standing principle names.

## §2 THE DIAGNOSIS, FROM THE BANKED ROWS

Instrument: the banked capture's own two legs (`real` = socketed chip,
`sim` = the fabric core on FLASH #13), diffed with `fuzz_classify.diff_rows`
over each seed's banked `compare_window`.  **The recomputed first divergence
reproduces the failure ledger's `first_bad_row` on 40 of 40.**

### 2.1 THE EXEMPLAR, ROW FOR ROW — `fz2c/400007`

    3320-3337  MEMW 53eec/53eea/53ee8    both legs   (a PUSH R tail)
    3345-3352  MEMR 00008 -> bf00
               MEMR 0000a -> 0000        both legs   the TERMINATING NMI's
                                                     vector, SUBSTITUTED
    3357-3373  MEMW 53ee6/53ee4/53ee2    both legs   PSW, CS, IP
    3374-3377  CODE 0bf00                both legs   the handler's first fetch
    3378       chip PASV                 core CODE 0bf02      <- FIRST DIFF
    3383-3390  chip MEMR 00004 / 00006   core: never          <- THE MISSED
                                                                 TRAP

The chip completes the NMI entry, issues exactly one prefetch of the handler,
and **then services a single-step trap that was pending when the NMI was
recognised.**  The core executes the handler instead.  This is the
architectural behaviour the survey's candidate law describes.

### 2.2 THE SAME SHAPE, MEASURED OVER THE POPULATION

Over the 32 scoreable seeds (§4), the chip's unmatched vector-1 read and the
last interrupt entry before it, both legs:

* **19 seats**: both legs read vector 2 at the **identical rows**, then the
  chip reads vector 1 at `+32 … +101` and the core reads nothing.  The
  vector-2 read is the terminating NMI's on every one.
* **2 seats** (`fz2e/531000`, `fz2e/531036`) have an `INTA` pair and vector
  `0xFF` in the same position — the same shape with the maskable door — and
  **both are OUT of the scoreable set** (§4.2), because the TB has one event
  scheduler and cannot deliver a stimulus INT.
* **9 seats** have **no** external entry within 140 rows.  On 8 of them the
  chip's rows read: IHT handler → three `MEMR` pops (an `IRET`) → two `CODE`
  fetches at a new `CS:IP` whose first byte is **`0xF4`** → the vector-1
  read.  The core executes the `HLT` instead and never comes back.  The
  ninth, `fz2e/518039`, is different again: **both legs read a vector-1
  there**, the core's read is at `0x00006` with no `0x00004` before it, so
  §38.9's predicate (*"the core reads no vector there"*, first halves only)
  admitted it on a technicality.

### 2.3 WHAT THE RTL SAYS, AND IT AGREES WITH THE ROWS

`v30u_eu_step.svh:55-56`, `:685`, `:736`, `:755` and `v30u_eu_row.svh:228` —
the five sites §86 calls "the five sites that already reach `S_IRQ_D`" — all
read:

    irq_sel_brk_n = !irq_take;      // §86: an EXTERNAL recognition wins
    brk_arm_n     = 1'b0;           //      ...and the arm is spent either way

**"…either way" is the defect.**  `brk_arm` is the latched pending trap.  At a
boundary where a maskable/non-maskable recognition and an armed trap coincide,
the ucore walks through the external door **and throws the arm away**.  The
chip walks through the external door and **still owes the trap**, which it
pays at the entry sequence's own end boundary — which is why the vector-1 read
lands after exactly one handler prefetch.

## §3 THE LAW — ONE PREDICATE, ONE TERM, NO OPCODE NAMED

> **AN EXTERNAL RECOGNITION DOES NOT SPEND THE SINGLE-STEP ARM.  ONLY THE
> TRAP'S OWN TAKE DOES.**

`L1`, the primary form — at the same five sites, and nowhere else:

    brk_arm_n = 1'b0;            ->   brk_arm_n = brk_arm_n && irq_take;

`irq_take` is already the term the line beside it uses to choose the door
(`irq_sel_brk_n = !irq_take`), so no new wire, no new flop, no new save-state
address, no change to `SS_VERSION`, and nothing in the BIU.

**INERTNESS, BY CONSTRUCTION.**  The edit can only change behaviour on a clock
where `at_bnd && irq_take && brk_arm` — an instruction boundary at which an
external interrupt is recognised *while a single-step trap is already armed*.
Where `brk_arm` is 0 the new expression is 0, which is what the old one wrote.
**Every `HLT.INT` / `HLT.NMI` / `HLT.RES` golden and every sweep cell runs with
`PSW.TF` clear**, so the whole `check_core` and HLT-sweep surface is predicted
BIT-IDENTICAL, not merely "no worse" (P-6).

`L2`, the fallback, taken only if `L1` misses a registered bar and only with
its own erratum stated: `brk_arm_n = brk_arm && irq_take` — the REGISTER
value rather than the possibly-just-sampled next value, i.e. a sample that
rides the same clock as an external take does not survive it.

## §4 THE INSTRUMENT, AND ITS VALIDATION RULE

### 4.1 THE ORDER THIS HAPPENED IN

`sw/fz2_c1_rescore.py` was written, its docstring's validation rule fixed, and
its BEFORE leg run over all 725 retained captures, **before** the predicate in
§3 was chosen and **before** any RTL was edited.  The scoreable set below is
therefore derived from a BEFORE-leg measurement, which is exactly what it is
for; the predicate was then chosen by reading rows (§2) and by reading the RTL
(§2.3), not by scanning for a term that improves a score.

### 4.2 WHAT IT IS

One line of difference from `fz2_a1_rescore.py`: the rig's `TVEC`
substitution is a CONSTANT (`fuzz_campaign.TERM_TVEC = (0x0000,
testimage.TERM_AT)`, the same CS:IP for every seed in the corpus), so it is
EMULATED IN THE IMAGE — bytes 8..11 (IVT entry 2) are overwritten with that
`IP, CS` pair **after** the seed's `image_sha256` has been asserted against
its banked value — and the comparison then runs over the seed's own banked
window with **no cut at all**.

Three ways it can be unfaithful, all stated in the source, all IDENTICAL in
the before and after legs, so each can hide a gain and none can manufacture
one: a seed that reads `0x8..0xB` as data; a seed with a stimulus pin event
(the TB has one scheduler and spends it on the terminator); a seed that writes
`0x8..0xB` before the terminator fires.

**THE VALIDATION RULE (fixed in the source before the BEFORE leg ran).**  A
seed is `SCOREABLE` iff its BEFORE-leg first divergence equals the value the
failure ledger recorded for it **chip-vs-FABRIC on the board**
(`first_bad_row`), or — for a seed the ledger does not name — iff the BEFORE
leg is row-clean over its banked window.  Anything else is `OUT` and is
counted in neither direction.  This is a falsifiable claim about the replay's
fidelity through the terminating NMI's entry, checked against a number taken
with a different instrument on different hardware.
