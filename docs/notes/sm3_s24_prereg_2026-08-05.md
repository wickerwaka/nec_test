## 2. WHAT IS UNDETERMINED, PRECISELY

§84.3's own words: the floor is *"bounded by the data to **[3, 6]** and no value
in that interval is separable on this population"*, because the only two
opcodes that raise `TF` in the whole bank are `9D` (rise **1-2** clocks before
its own retire) and `CF` (**6-26**), **with nothing in between**.  3 was
**CHOSEN**, not measured — chosen because it is `evpipe`'s existing depth and
therefore not a new constant.  §84.3's registered falsifier is:

> any instruction whose `TF` rise is **3, 4 or 5** clocks before the retire that
> must sample it — that case separates [3, 6] and **this tree has none**.

**This cell manufactures that case, forty times per capture, at five distinct
distances.**

## 3. THE STIMULUS — one knob, and it is an instruction

Every sled is a PERIOD repeated ~70 times, every instruction start known:

    popf<pad>   9D ; <PAD> ; 90 ; 90 ; 90 ; 90 ; 90
    iret        CF ; 90 ; 90 ; 90 ; 90 ; 90        (CF pops a PLANTED frame)

`9D` pops a planted `0xF102` — **BRK/TF set, IE CLEAR** — so `TF` rises at the
setter's own `E` row and **no pin is driven anywhere in this cell**.  Write `Bj`
for the retire boundary of the sled's instruction `Ij`.  `B0` is 1-2 clocks
after the rise; **`B1`'s distance is the pad's clock length added to that**, and
that is the axis.  The wait level stretches the same pad, giving a second,
independent point per sled.  Measured off the engine's own retire trace
(`V30SIM_BRKTRACE`, the `walk` column below), `dist(rise → B1)` takes the values

| w0 | 2 (`clc`) · 3 (`inc`, `test`) · 4 (`none`, `xchg`, `add`) · 5 (`movi`) · 13 (`memr`) · 25 (`mul`) |
|---|---|
| **w3** | **3** (`clc`) · **4** (`inc`, `test`) · **5** (`none`, `xchg`, `add`) · **6** (`movi`) · 20 · 26 |

— i.e. **the whole of [3, 6], from both sides, plus 2 below it and 13/20/25/26
far above it as saturated controls.**

## 4. THE OBSERVABLE — read off the pins, NO ENGINE

A vector-1 entry pushes exactly three words, SP descending: PSW, CS, **IP**,
announced by the two IVT reads below `0x400`.  No sled emits any other
three-in-a-row descending word write (the handler's single `MOV [BP+4]` is one
write, not three).  The third push is the RETURN ADDRESS — **the boundary the
part chose** — and every sled is periodic, so

    phase = (pushed_IP − PC0) mod period

names it exactly.  This is §72's reader, one vector over.  The handler CLEARS
`TF` in the frame it returns through, so each setter yields exactly ONE trap and
the sled free-runs to the next setter: **~40 independent repeats of the same
measurement per capture.**

**THE ARITHMETIC, so the table below is checkable by hand.**  The law takes at a
boundary when the arm stands, and samples `TF` into the arm afterwards.  So if
`Bj` is the FIRST boundary whose sample sees the rise, the trap is taken at
`B(j+1)` and the pushed IP is the start of `I(j+2)`.  `B0` never sees the rise
under any floor ≥ 3, so the whole question is one bit:

    dist(rise → B1) ≥ floor  →  trap at B2, pushed IP = start of I3
    dist(rise → B1) <  floor  →  trap at B3, pushed IP = start of I4

## 6. THE REGISTERED BARS — **stated before the run, reported as registered**

* **W-0a — THE NULL.**  The TF-CLEAR controls `notfnone`, `notfclc`, `iretnotf`
  are the identical geometry with `0xF002` planted instead of `0xF102`.  They
  must yield **ZERO** vector-1 entries on the chip, at every wait and every
  repeat.  **Bar: 0.**  A non-zero count means the three-descending-writes
  pattern is not the trap, and the cell is VOID — no verdict is taken from it.

* **W-0b — THE CLOCK RULER.**  The floor is quoted in CLOCKS, and the clock
  coordinate of the rise is the ENGINE's; it is credible exactly as far as the
  engine reproduces the chip's bus per clock on these sleds.  The TF-clear
  controls contain **no law at all**, so they measure the ruler and nothing
  else.  **Bar: 0 row-diffs** (`fuzz_classify.diff_rows`, the repo's own column
  policy) over the full retained window, chip vs engine, on all three controls
  at both wait levels.  **IF IT IS NOT 0 THE CLOCK-VALUED VERDICT IS WITHDRAWN**
  — the ORDINAL verdict (which boundary the chip traps at) survives, because
  that is read off the pins with no engine, but no number of clocks may then be
  quoted for the floor.  This is written down now so it cannot be renegotiated
  after the fact.

* **W-1 — DETERMINISM.**  Nothing external is driven; the run is deterministic
  from RESET.  **Bar: the 3 repeats of every cell have IDENTICAL phase
  histograms.**  A disagreement is a rig-integrity FINDING and a hard STOP.

* **W-2 — THE FLOOR.**  Let `S` = the intersection, over all 22 scored
  `popf*`/`iret` cells, of `{F : engine(F) histogram == chip histogram}`.
  **Bar: |S| == 1.**  The dispositions, ALL of them registered now:

  | `S` | disposition |
  |---|---|
  | **{3}** | law B and its constant CONFIRMED.  The sim landing's PROVISIONAL status **LIFTS**.  §84.3's falsifier is exercised and does not fire. |
  | **{4}**, **{5}** or **{6}** | the law SHAPE is confirmed and the CONSTANT is WRONG.  `kBrkFloorDefault` is corrected to the measured value — a PRE-REGISTERED constant fix, not a new law — the full §84.4 ladder is re-run, and the landing lifts on the corrected constant.  The `evpipe`-depth justification for 3 is then RETIRED as a coincidence that was never evidence. |
  | **{1}** or **{2}** | the floor is BELOW the bound §84.3 derived from its own selecting population, which contradicts that population's `9D` branch.  **REFUTATION**: the sim landing is REVERTED. |
  | **∅** | no single floor explains the chip → the one-floor / one-arm-bit shape is REFUTED.  The sim landing is REVERTED. |

  **DISAMBIGUATION, registered in advance:** `popfpfx` is the one sled whose
  prediction also depends on the PREFIX-SAMPLES clause.  If `popfpfx` is the
  ONLY cell whose floor set excludes an otherwise-unanimous value, that indicts
  **the prefix clause**, not the floor; the floor verdict is then taken on the
  remaining 20 cells and the prefix clause is booked as a separate open item.
  No other cell gets this treatment.

* **W-3 — THE ASYMMETRY IS NOT AN OPCODE RULE.**  `iret` and `popfnone` have the
  SAME 6-byte period and the same NOP run, and differ only in the setter.
  **Bar: `iret` traps ONE boundary EARLIER — chip phase 2 against `popfnone`'s
  3 — at BOTH wait levels.**  This is law A's observation reproduced on a
  directed population, and under law B it is a CONSEQUENCE of the floor rather
  than a clause.  A failure here refutes the one-floor reading regardless of W-2.

* **W-4 — A PREFIX BOUNDARY SAMPLES BUT DOES NOT TAKE.**  In `popfpfx` the byte
  at period offset **2** is the prefixed opcode, i.e. NOT an instruction start.
  A trap TAKEN at the prefix boundary would push exactly that address.
  **Bar: ZERO entries with phase == 2.**  Its appearance refutes the
  take-at-retire clause and is a falsifier of the landed law as written
  (`sim/exec_impl.h`: *"any trap taken at a prefix boundary"*).

* **W-5 — THE STORM CADENCE (§84's V-2, one instrument over).**  `storm` routes
  vector 1 to the bare `IRET` handler, which RESTORES `TF`.  **Bar: the phase
  sequence advances by exactly ONE instruction index per entry, on every
  consecutive pair** — grace 0.  V-2 was MET on the banked population; this is
  the directed re-run.

* **W-6 — PER CLOCK, AT THE WINNING FLOOR.**  Reported, not barred, because no
  prior number exists for it: chip vs engine row-diffs over every capture at
  each surviving floor.  It is the sharper statement the ordinal verdict cannot
  make, and it is scored with the repo's own column policy.
