# INS microcode-EU offline pilot — 2026-08-01

Question: does the actual EU micro-sequencer mechanism (the ROM in
`docs/V20UC.TXT`, boundary analysis in `docs/notes/microcode_analysis.md`)
predict the Case 250 INS factorial planes from a few GLOBAL constants,
where the FSM EU currently needs a per-(off,len) rail forest and still
fails four cells?

**Verdict: YES.  Write rails 1312/1312 exact across all four families,
constants frozen on two families and validated untouched on the other two,
including the four `fz12569 C1` w12/w14 cells the FSM RTL fails.**

Runner: `sw/ins_ucode_pilot.py` (offline only; reads the retained
`sw/case250_fz*_factorial.json`, chip side only).

## Mechanism → law mapping

The ROM's INS sequence (rows `0318`–`0347`, entry shared by 0F 31 reg and
0F 39 imm forms) is a single sequential micro-march with:

- `MEMR ES` at `031B`/`0337` (R1/R2 issue), `MEMW ES` at `032F`/`0343`
  (W1/W2 issue);
- `F`-flagged rows (`031C`/`0344`, `033D`) — the OPR interlock, the only
  EU↔bus synchronization;
- `Q→tmpaL` at `0347` — the imm-byte queue pop (imm form only);
- `R`-column `MUL`/`SHR` rows — COUNT-driven iterative shift loops, with
  COUNT loaded from the bit offset (`0319`) and from offset+length
  (`0320`–`0322`).

That structure forces every geometry dependence to be **linear in
S = off + len** (or in `off` alone), and the max-of-two-deadlines shape to
emerge from one march with an F-stall — not from two independent rails.

## Laws (global constants only)

With the campaign-3 eval law `e(x) = 1 if x.tw > 0 else 0` (completion
eval at T3→T4 for zero-wait cycles, during the post-T4 cycle otherwise),
and R1/R2 = final (high) halves for split accesses:

```text
W1.T1 = max(R1.T4 + e(R1) + 3*S + 30,     # R1-anchored march (both loops)
            R2.T4 + e(R2) + 2*S + 9)      # R2 F-stall + tail loop only
W2.T1 = W1.T4 + 1 + e(W1)                 # split high-half write chain
R2req = R1.T4 + e(R1) + 18 + off          # off-count loop, then issue
R2.T1 = max(R2req, busfree + 2)           # BIU grant on the 2-clock grid
```

The published per-family oracle deltas are exactly these lines:
`decoder_delta = 3S + 30`, `completion_delta = 2S + 9` (54/25 at S=8,
57/27 at S=9, 63/31 at S=11).  The imm and reg forms share intercepts —
consistent with the ROM's equal row counts on the two paths
(`031C`–`031F` vs `0344`–`0347`).

  not EU state.

## Implications

1. The four-cell `case273` residual (fz12569 C1 w12/w14) is an artifact of
   the FSM rail encoding (`ie_r2_late` composed with an absolute deadline),
   not missing chip state: the single-march max law predicts those cells
   exactly with no phase hold and no special case.
2. The ~8 per-geometry qualifier families and ~79 fitted rail constants in
   `v30_eu.sv` for INS collapse to 4 global integers (3, 30, 2, 9) plus
   the eval law and one issue constant (18+off) — all generated by loop
   counts visible in the ROM.
3. The model **predicts unseen geometries** (any off/len via S), where the
   rail approach needs a new factorial per geometry cell.  This is the
   generalization property the acceptance boundary requires.
4. Within these planes the imm-byte Q-pop never became the binding
   constraint (the 60+-clock burn hides queue latency); queue-dry stalls
   on `0347` remain untested by this data and need a directed probe if
   INS-with-starved-queue matters.

## Limits (honest ledger)

- Four (off,len) points, all on the S-line; slopes 3/2 fit these planes
  but the decomposition into individual loop costs is not uniquely
  identified from this data.  A directed off/len sweep (held-out S values,
  off varied at fixed S) would pin it and is cheap.
- R2-issue grid parity (18/800 cells ±1) is deliberately left to the BIU
  grid model, not patched here.
- This is an offline law-level demonstration of the micro-march mechanism,
  not yet an RTL micro-sequencer.

## Suggested next steps

1. Directed chip factorial over held-out (off,len) — freeze the S-law
   first, then validate; this is the prospective gate the linear law has
   not yet passed.
2. Decide the RTL migration: replace the INS rail forest in `v30_eu.sv`
   with the march model (deadline = S-linear counters + F-stall), gated on
   the existing 640/800-record planes plus the 352-record prior INS
   regression.
3. If GO on the broader microcode-EU track: repeat this pilot shape on the
   next-worst rail family before committing to a full micro-sequencer.
