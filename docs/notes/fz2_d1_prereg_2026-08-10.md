## 1. THE MECHANISM, MEASURED

### 1.1 The failure is one cell, and it is the same cell every time

All 115 failures across the four cells are `INT.F3AA` and each has **exactly
one** bad cell: `(row, qop) exp 'E' got '-'`.  (`max nmm over failures: 1,
all-single: True` on every cell — instrument §5.)  `arch` is perfect on all
four; nothing architectural is involved.

### 1.2 The rails at the withdrawal partition the population EXACTLY

A temporary `+ftrace` on the REP-withdrawal flush rails (added, read, and
**reverted before any gate ran**; §5) classifies every clock on which
`q_flush && flush_rep`.  Over the five golden populations:

| population | cases | REP-flush clocks | `QSE=1` | `QSE=0` | fails |
|---|---|---|---|---|---|
| `tests/v30/v0.1` (**all 347 forms**) | 169,000 | **56** | 56 | **0** | 0 |
| `v0.1-w0evt` | 200 | 75 | 75 | **0** | 0 |
| `v0.1-w1evt` | 1,200 | 73 | 42 | **31** | 31 |
| `v0.1-w2evt` | 200 | 62 | 39 | **23** | 23 |
| `v0.1-w3evt` | 1,200 | 63 | 39 | **24** | 24 |
| `v0.1-w1evt-biased` | 1,200 | 87 | 50 | **37** | 37 |

Totals: **416** REP-withdrawal flush clocks over **173,000** cases — **301
`QSE=1`, 115 `QSE=0`**, and **115 failures**.

**Every case whose REP-withdrawal flush clock shows `QSE = 0` FAILS.  Every
case whose flush clock shows `QSE = 1` PASSES.  There is no third class and no
exception in 416 flush clocks over 173,000 cases.**

On every one of those 416 clocks, without exception:
`flush_pend = 0`, `flush_direct = 0`, `flush_fast = 0`, `flush_nmi_young = 0`,
`flush_int_live = 1`.  The `QSE=0` clocks are further unanimous:
`e_from_block = 1` and `qs_port_fetch = 1` — **a CODE fetch owns the queue
status port on the flush clock**, which is exactly why `qs_e_now` cannot show
`EMPTY` there.  (`flush_stage` splits both classes and predicts nothing: over
the 115 `QSE=0` clocks it is 0 on 83 and 1 on 32, and it takes both values on
the passing `QSE=1` clocks too.)

### 1.3 The coverage hole, named and sized

**In all 169,000 w0 goldens, `INT.F3AA` is the ONLY form that produces a
REP-withdrawal flush clock at all — 56 of them — and every one is `QSE = 1`.**
The `QSE = 0` class does not exist at w0.  `9c98117a03`'s registered gates were
`check_core --opcodes all` at w0 plus the w0 `INT.F3AA` cell; **no w0 gate can
reach the class this document is about.**  That is the hole, stated plainly.
The repair itself is measured green and stays.

### 1.4 The defect: two sites that must agree, and only one was ever repaired

`v30u_biu.sv` decides the REP-withdrawal `EMPTY` in **two places**.

*The display*, in `qs_e_now` (line ~687) — suppressed on the flush clock when
the redirect takes the arbitration point that carries the announcement:

    !(q_flush && flush_rep &&
      (flush_direct ||                                   // <- the direct arm
       (flush_pend && !flush_src_live &&
        !(r_run && !r_cur_fetch && (r_ts < TS_T3)))))    // <- the staged arm

*The owe*, in `flush()` (line 1642) — what to do when the display did **not**
happen on the flush clock:

    if (!qse_l && !(flush_rep && !flush_pend)) e_pend = 1'b1;

`flush_direct` is `!flush_stage && !flush_nmi_young && !flush_int_live`.  It
has been **narrowed twice since L1** — `flush_nmi_young` at L1, and
`!flush_int_live` by `9c98117a03`, whose whole subject is *"the asserted pin
withdraws the direct arbitration point"*.  **The owe site never received either
narrowing.**  It still reads the L1-era stand-in `!flush_pend`, which is `1` on
every one of the 338 measured flush clocks, so it reduces to plain `flush_rep`
and drops the `EMPTY` unconditionally.

The consequence is visible only when the flush clock cannot show `EMPTY` for an
*unrelated* reason — a fetch owning the queue port — because only then does the
owe latch matter.  At w0 that never happens.

**THE LAW, ONE SENTENCE:** *the flush clock's `EMPTY` is owed to the next free
clock unless the redirect actually took the direct arbitration point* — and
`flush_direct` is the rail that already says so.

## 2. THE LANDING — `L1`

`hdl/rtl/ucore/v30u_biu.sv`, **one term added in one expression**, reading a
wire that already exists and that the display site already reads:

    -  if (!qse_l && !(flush_rep && !flush_pend)) e_pend = 1'b1;
    +  if (!qse_l && !(flush_rep && !flush_pend && flush_direct)) e_pend = 1'b1;

**No flop.  No save-state address.  No port.  No new wire.  No opcode named.
No case split.**  It is the same idiom `9c98117a03` used when it made three
open-coded copies of one condition read one name.

**IT IS A STRICT NARROWING OF A SUPPRESSION**, so it can only cause an `EMPTY`
to be **owed** where one was previously **dropped**.  It can never remove an
`EMPTY` the tree shows today.

**WHAT IS DELIBERATELY NOT TAKEN, with the reason.**  `flush_fast`
(`= flush_rep && flush_idle && flush_direct`) is the rail that says the direct
T1 *actually opened*, and it is arguably the truer predicate.  It is **not**
used, because `flush_idle` is a second, unmeasured narrowing: on all 416
measured clocks `flush_direct = 0` already, so the two forms are
indistinguishable on every population this tree can score, and the smaller
change is the one that is evidenced.  Likewise `!flush_pend` is **kept** though
it is `1` on all 338 clocks — removing it would be a change with no measurement
behind it.  **FALSIFIER for both omissions:** a REP withdrawal with
`flush_direct = 1` (or `flush_pend = 1`) on a clock where the display was
blocked, and where silicon disagrees with the owe this landing makes.  **No
such instance exists in 173,000 golden cases** — `flush_direct` and
`flush_pend` are 0 on every one of the 416 REP-withdrawal flush clocks in the
entire golden corpus.
