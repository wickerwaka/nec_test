## §2 THE DIAGNOSIS — AND IT IS **ONE LAW**, NOT THREE

Derived from the golden ROWS (silicon), cell by cell, offline.

### §2.1 The pin group, seen whole

`check_core`'s `bus` column is `ad_addr` on a T1 row and `{ps, ad_data}`
everywhere else — so `ps`, the A19-16 sample, is directly readable on every
non-T1 row. Read that way, `s10-hltsweep-w0 HLT.INT idx 4` says:

```
row  T   status  GOLDEN ps          ucore ps
 6   T3  CODE    5  (the ADDRESS)   5     <- the wake fetch's DISPLAY clock
 7   T4  CODE    6  (data_ps(CS))   5     <- family A
 8   T1  CODE    6  (late T1)       6     <- M23's `t1_addr`, already correct
 9   T2  PASV    6                  6
10   T3  INTA    0  (the "address") 0     <- the acknowledge's DISPLAY clock
11   T4  INTA    6  (data_ps(CS))   0     <- family C
12   T1  INTA    6  (a LATE T1)     0     <- family C
```

**Families A and C are the same sentence twice.** M23 already states the law —
*"the address one-shot is fired by the DISPLAY and is ONE CLOCK LONG; where the
bus made the T1 wait it has already expired and A19-16 is back on the segment
status"* — and `v30u_biu.sv` enforced it on the **T1** side only (`t1_addr`,
gated by `cur_late_t1`). On the DISPLAY side `display ? r_cmt_addr` republished
the whole 20-bit address for every waiting clock (family A, F52's diagnosis) and
`(disp_inta || cur_inta) ? 20'h0` did the identical thing one cycle-type over
(family C). **An INTA has an address phase too; its value is simply zero.**

### §2.2 UBE is the same one-shot's other pin

`s13-hltsweep-w2 HLT.INT idx 10` rows 12-13 and `-w3 idx 12/13/14` rows 14-15:
the wake fetch's announcement is **WITHDRAWN** (the acknowledge takes the bus),
the chip keeps `ube 0` — the withdrawn announcement's own UBE, by pad retention
— and the ucore reverts to the HALT pseudo-cycle's `1`, because `ube_n`'s middle
term was `r_run ? r_cur_ube_n`, i.e. a *running* cycle re-drives its UBE on
every clock of its body. **This is ucsim-t §26.7.7's open item** (*"after a
WITHDRAWN multi-clock announcement the pads retain the WITHDRAWN cycle's address
and UBE"*), seen from the RTL side. Family E.

### §2.3 THE LAW (one statement, both pins)

> **F53. The address phase is ONE CLOCK, on both sides of the pin mux and for
> both kinds of address.** A19-16 carries the announced cycle's address-phase
> value for exactly the display clock (`r_cdage == 0`) — the address's own
> A19-16 for a cycle that has one, `0` for an INTA, which does not — and
> `data_ps(seg)` on every clock after it, up to and including a LATE T1. UBE is
> **loaded by the address phase and then HELD**; it is not re-driven by a cycle
> that is merely running, so a withdrawn announcement's UBE stands on the pads.

No flop is added; nothing outside the pin mux is touched; there is no per-cell
table, no segment logic and no second HALT display.

### §2.4 Family D is NOT this law, and it is diagnosed separately

`w1.INT/8,9 · w2.INT/12 · w3.INT/15`. The chip's analyser has **TWO** samples of
`BS` per CPU clock — `bs_early`, registered at the FALLING edge, which is the
value in the row's status column, and `bs_q`, registered every system clock, so
at `tick_rise` it is the END-of-clock value and it is what `next_t_state` reads
(`nec_bus.sv:188-197, 297, 339-345`). On these four cells the golden carries
`bs_early != PASV` on the last clock of a withdrawn window **and** `t == Ti` on
the row after — i.e. the announcement's status is present at mid-clock and gone
by the end of the same clock.

**MEASURED, and it is exactly the four cells**: over all four sweeps' goldens,
the pattern `bs(r) != PASV ∧ t(r) ∈ {T4,Ti} ∧ t(r+1) == Ti` occurs
**4 times in 15,358 rows** — `w1.INT/8` row 10, `w1.INT/9` row 10,
`w2.INT/12` row 12, `w3.INT/15` row 14 — and nowhere else. The ucore's `bs` is a
whole-clock level, so both of the analyser's samples see the same value and the
pattern is unreachable. `tb_v30_core.sv` has only ONE sample and uses it for
BOTH the recorded column and its own tracker, so on that TB the cells are
unfixable **by construction**; on `tb_sys` and in fabric, where the analyser is
`nec_bus` itself, a half-clock status release WOULD be scoreable.

**Family D is therefore BOOKED, not landed here.** It is a different mechanism
(*when within the clock the status register releases on a withdrawal* — the
F43/H1 shape), it needs its own authorising evidence, and folding it into F53
would be fitting.

### §2.5 Family B stays booked

4 cells, `w0.INT/2,3` · `w0.RES/2,3`, `(4, busstat) CODE→PASV`: the whole
capture is shifted one row — the wake display fires one clock later than
silicon. **Model-shared** (§76.B.2: byte-identical to the model's), so `sim/`
owns the mechanism and this sitting does not open it.

## §3 THE CHANGE — TWO TERMS AND A THIRD, ALL IN THE PIN MUX

`hdl/rtl/ucore/v30u_biu.sv` only. No flop added. F52's preserved diff is the
**display-side half**; the INTA half and the UBE half are new.

```systemverilog
assign ube_n = (display && (r_cdage != 3'd0)) ? r_cmt_ube_n
             : (r_run && (r_ts == TS_T1))     ? r_cur_ube_n   // was: r_run ?
                                              : last_ube;

wire [3:0] disp_hi  = (r_cdage == 3'd0) ? r_cmt_addr[19:16] : data_ps(r_cmt_seg);
wire [3:0] dinta_hi = (r_cdage == 3'd0) ? 4'h0              : data_ps(r_cmt_seg);
wire [3:0] cinta_hi = r_cur_late_t1 ? data_ps(r_cur_seg) : 4'h0;

assign ad_o = disp_inta ? {dinta_hi, 16'h0}          // was: (disp_inta||cur_inta) ? 20'h0
            : cur_inta  ? {cinta_hi, 16'h0}
            : display   ? {disp_hi, r_cmt_addr[15:0]}  // was: display ? r_cmt_addr
            : ... unchanged ...
```

The mux PRIORITY is unchanged (`disp_inta`, then `cur_inta`, then `display`),
so no case outside the address phase moves.

## §4 THE AUTHORISING POPULATION — THE DIRECTED DISPLAY WALK (S16)

`sw/sm3_s16_cell.py`. **It did not exist when anything was scored**, which is
what §76.D.3 requires. FROZEN BEFORE CONTACT, and printed by
`sm3_s16_cell.py plan`:

* **3 forms** — `HLT.INT` (ie=1, status nibble `0x6`), `HLT.RES` (ie=0, `0x2`),
  `HLT.NMI` (ie drawn per program, either);
* **6 programs per form**, each ONE frozen RNG draw
  (`v30-sm3-s16/<form>/p<N>`), giving 18 distinct `CS:IP` and therefore 18
  distinct wake-fetch A19-16 nibbles. The s10/s13 sweeps run **one** program per
  form and its wake nibble is `5`, a LEGAL status code — ucsim-t §26.7's
  confound. The 18 split **7 IMPOSSIBLE** (nibble ≥ 8: it sets the 8080
  emulation-mode bit, which no segment status can carry in a capture that is not
  in emulation mode, so the nibble NAMES ITSELF as the address), **9
  legal-diff**, **2 SAME** (the confounded control the sweeps are);
* **4 wait levels** × **21 delays** (0..20), which contains the
  `H … H+waits+1` band at every level with margin on both sides;
* **1,512 cells**, each emitted BOTH as a standard golden
  (`tests/v30/s16-dispwalk-w<w>-p<p>/<form>.json.gz`, so `check_core` scores it
  with no new machinery) AND as raw words + full rows + sha256.

### §4.1 THE REGISTERED PREDICTIONS ABOUT SILICON

| | prediction | bar |
|---|---|---|
| **S1** | on every display window of length ≥ 2, A19-16 on the **display clock** is the announced cycle's own address nibble (`0` for INTA) | **100 %** |
| **S2** | on every clock of such a window **after** the display clock, A19-16 == `data_ps(seg)` | **100 %** |
| **S3** | on every **LATE** INTA T1 (T1 > display+1), A19-16 == `data_ps(seg)`; on a non-late one it is `0` | **100 %** |

reverted regardless of its score; the exception is reported as a refutation and
not re-explained.
