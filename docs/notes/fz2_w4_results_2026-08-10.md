### 3.2 THE MECHANISM OF THE REFUTATION, NAMED

**`halted` is not the ucore's prefetch SUSPEND; it is its permanent PARK, and
it has exactly one release.**  Its declaration says so —
`reg halted; // S8/S9: once halted the prefetcher never runs again` — and the
only thing that clears it is `eu_unhalt`, which is `hlt_wake_int ||
unhalt_pend`: the first requires `st == S_HALTED`, and the second is set only
in the `S_IRQ_D` arm when `eu_halted` is up.

**A `HLT` that retires into a trap never enters `S_HALTED`** — that is P2's
`L-B`, the `&& !brk_seen` at `S_DECODE2` — so on precisely the two seats this
package was built for, nothing can ever clear `halted`.  Routing the trap case
into it **kills the prefetcher for the remainder of the program**, which is the
measurement: the first divergence moves 37 and 49 rows later (the extra fetch
the seats were about IS gone) and then the rest of the window diverges.

`fz2c/407064` (family `B1`) moved for the same reason: it is a `HLT` seed, so
it too crosses the changed line.

### 3.3 WHAT IS BOOKED, WITH TWO FALSIFIERS

**C-α′ — the trap-cancelled `HLT`'s prefetch suspend is the FLUSHABLE one.**
Silicon stops fetching at the `HLT` and starts again at the trap's own
redirect.  In this core's vocabulary that release already exists: `q_flush`
sets `suspended = 1'b0` and raises `pf_owed`.  So the suspend a trap-cancelled
`HLT` wants is `suspended`, not `halted`.
*What blocks it, stated so the next sitting does not re-discover it*: the naive
form — adding `if (eu_halt_susp) suspended = 1'b1;` beside the existing
`halted` line — **also fires on an ordinary `HLT`, and `eu_unhalt` does not
clear `suspended`.**  `HLT.RES` is a masked-`INT` wake that resumes the stream
**without vectoring**, so it has no flush to release it, and the prefetcher
would never restart.  **`s10-hltsweep-w0`'s `HLT.RES` 49/49 is the falsifier
for that form and it is why it was not built.**  Writing it as
`eu_halt_susp && !eu_halt` would be a two-cased rule, which the standing design
principle says is a signal of misunderstanding — so the honest next step is to
ask what the die's ONE prefetch-suspend is and why this core has two, not to
add a third case.
*Falsifier for the law itself* (unchanged, and it is in no RTL because nothing
landed): a capture in which the chip issues a prefetch between the `F4` that
retires into a trap and that trap's own vector read.

**C-β — the PARK COST when the display is cancelled.**  Registered in advance
(§3.1 of the pre-registration) as NOT reachable by the port split, and measured
as not reachable: the three `C2` `sti; hlt` seats did not move by one row.  On
silicon the part spends **two idle clocks** before its first `INTA` T1 with the
display already cancelled by F54's law; `hlt_wake_int` fires on the ucore's
first `S_HALTED` clock, so a cancelled display costs it nothing.
*Owner*: `v30u_eu.sv`'s `S_HALTED` / `hlt_wake_int` geometry.
*Falsifier*: a capture in which `sti; hlt` with the pin already high delivers
`INTA` with NO idle clocks between the `HLT` boundary and the acknowledge.
Seats: `fz2c/404071` @244 · `fz2e/514044` @235 · `fz2e/516001` @584.
**Not fitted on this population**: a two-clock hypothesis chosen by reading
these three seats and then scored on them is what §64.1 forbids.
