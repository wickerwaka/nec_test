## §1 THE QUESTION, AND WHY THE OLD CELL COULD NOT ASK IT

§71 built the ENTRY-GENERIC arm, scored it 791/791 on its own cell, and saw it
REFUTED by five NMI seeds on the disjoint bank.  §71.6 recorded what survives:

> the entry clears IE (`CITF`, `01F5`); the handler's IRET pops a PSW that
> RAISES it; **a maskable recognition cannot act on a rising IE.**  A planted
> frame popping IE = 1 into IE = 1 has no rise and is unfloored.  An NMI is not
> IE-gated and has nothing to wait for.

Its blocker was named as an instrument: `sm3_h1_cell.py --variants clipopf`
(a `CLI ; POPF` chain) produced **NO ACKNOWLEDGE AT ALL** in 24 captures, and
§61.3 booked that as an open observation.

### §1.1 THE `clipopf` DIAGNOSIS — **THE STIMULUS IS NOT BROKEN.  ITS SILENCE
### IS THE PREDICTED BEHAVIOUR OF THE HYPOTHESIS IT WAS BUILT TO TEST.**

Read off the 24 RETAINED captures in `sw/testdata/sm3-h1cell/`, chip side, no
engine, no board contact:

* the popped word is **`0xF202` on every POPF** — IE **is** set in the image.
  ("the popped PSW image's IE bit not actually set" is REFUTED);
* the chain **runs to completion** — 81 stack reads at `0x3F00`, `0x3F02`, …
  stepping by 2, then the harness epilogue and `HALT`.  It does not wedge, it
  is not skipped, and `fired = True` on all 24 (`manifest.json`), so the rig
  DID drive the pin;
* `hold = 300` on all 24, i.e. the level is held across ~25 iterations of the
  12-clock loop.  ("the INT level dropping before the rise" is REFUTED);
* the whole capture contains **0 INTA cycles and 0 memory writes** — no entry
  of any kind, so nothing was serviced between the CLI and the POPF either.

**And the program has no boundary at which a floored recognition could ever
act.**  `FA 9D FA 9D …` has exactly two boundaries per iteration: after the
POPF (IE has just RISEN) and after the CLI (IE is CLEAR).  Any law that
forbids the boundary at which IE rose, and tests IE live at the next one,
recognises **never**.  The fix is not to the rig: it is **PADDING**.

### §1.2 THE BANKED GOLDENS ALREADY SAY THE FIRST HALF OF IT

`tests/v30/v0.1/INT.9D.json.gz` (POPF) and `INT.FB.json.gz` (STI), 400 silicon
cases, read with no engine (pushed IP minus initial IP minus instruction
length = how many extra 1-byte NOPs ran before the entry):

| golden | population | `extra` |
|---|---|---|
| `INT.9D`, IE **1 → 1** (no rise) | 111 | **0** in 104, 1 in 7 |
| `INT.9D`, IE **0 → 1** (a RISE) | **89** | **1 in 89 of 89 — never 0** |
| `INT.FB` (STI, always a rise) | **200** | **1 in 160, 2 in 40 — never 0** |
| `INT.8ED0` / `INT.8ED8` (`MOV SS,r`, IE already 1) | 400 | never 0 — a SEPARATE, opcode-set shadow (`irq_shadow` in the ucore) |
| `INT.90` / `INT.B8` (IE already 1) | 400 | 0 occurs freely |

So on silicon **an IE RISE costs the raising instruction's own boundary, and
an unchanged IE costs nothing.**  What those goldens CANNOT say is what
happens at the *next* boundary if IE has gone down again — they are
single-instruction tests with a NOP sled behind them.  That is exactly what
this cell asks, and it is why the cell is needed even though the goldens exist.

**§64.1 COMPLIANCE.**  The IE reading was selected on the 3,242-seed fuzz bank
(§71.4's five NMI seeds), so **the bank cannot authorise it**.  These goldens
are standing gates that both engines already pass at 169,000/169,000; they are
CONTEXT, and they are NOT the authorising population either.  **Only the new
cell below authorises.**

## §2 THE CELL

`sw/sm3_h1_cell.py run --out sm3-s11cell`, socket only (`EMIT_USE_CORE` is
`False` and the module refuses to load otherwise), divider PINNED with
`div_guard`'s readback recorded, full per-clock rows + raw 64-bit words +
`SHA256SUMS` retained, `board_idle()` at the end, 5 consecutive transport
errors STOP the cell.  **NO FLASHING** — the board carries FLASH #5.

Four sleds, every instruction 1 byte, so the sled period in BYTES is the sled
period in BOUNDARIES:

| variant | sled | period | the IE-writing instruction's OWN boundary |
|---|---|---|---|
| `iepop` | `CLI ; POPF ; NOP ; NOP` | 4 | phase **2** |
| `iesti` | `CLI ; STI ; NOP ; NOP` | 4 | phase **2** |
| `iehot` | `POPF ; NOP ; NOP ; NOP`, IE already 1, popped IE 1 | 4 | phase **1** |
| `clipopf` | `CLI ; POPF` (§61.3's, unchanged) | 2 | phase **0** |

`iepop`/`iesti`/`clipopf` also have a **DEAD** phase — the boundary right after
the `CLI`, where IE is CLEAR (phase 1, 1 and 1 respectively).  `iehot` has none
by construction: it never clears IE, which is what makes it the control.

### §2.1 THE OBSERVABLE — the pushed frame, off the pins, no engine

Every interrupt entry pushes three words with SP descending: PSW, CS, **IP**.
No sled in this cell contains any other memory write, so a run of three MEMW
cycles stepping down by 2 **is** an entry, and its third word is the RETURN
ADDRESS — i.e. **the boundary the part chose**.  It reads identically for a
maskable acknowledge (INTA pair in front) and for an NMI (no INTA at all),
which is the only reason the two pins are comparable at all.

```
    phase = (pushed_IP - 0x0500) mod period
```

The reader is `sm3_h1_cell.entry_frames()` / `s11_phase()`, and it is
**VALIDATED ON RETAINED SILICON BEFORE ANY NEW CAPTURE**: on
`sm3-h1cell/nop_w0_d12` it reads `psw=0xF202 cs=0x0000 ip=0x0504`, on
`iretnext_w0_d12` `ip=0x0501`, on `callret_w0_d12` `ip=0x0503` — the correct
return address of each sled, and `psw = 0xF202` (IE **SET**) on all of them,
which independently confirms that silicon pushes the PSW **before** `CITF`
clears IE.

### §2.2 THE SWEEP

`--variants iepop,iesti,iehot,clipopf --pins 0,1 --waits 0,1,2,3 --delays 24
--d0 12 --hold 300`, minus `iehot:p1` (a control for the maskable law only) =
**7 legs × 4 waits × 24 delays = 672 captures.**

**w0 IS THE DISCRIMINATING REGIME** and it is the only one that carries a bar,
for §68.4's structural reason carried forward from §71.2: at `w >= 1` the
ordinary next-slot term `L+1` grows and swallows a 2-clock floor, so
"unfloored" is inexpressible there.  w1/w2/w3 are captured and reported and
carry NO registered outcome.

## §3 THE CANDIDATES

**IE** — *the IE-restore reading, §71.6.*  A MASKABLE recognition needs IE set
at the boundary **and** already set some clocks earlier; it cannot act on a
rising IE.  A NON-MASKABLE recognition is not IE-gated and is never floored.

**NOFLOOR / ENTRY** — *any surviving entry-anchored reading, including H1's
landed INTA-only arm.*  There is no floor without an interrupt entry (or an
acknowledge) behind the boundary.  An IE rise costs nothing.

**INHIBIT** — *an opcode-set one-boundary inhibit flag* (x86's documented
`STI` / `MOV SS` shadow, generalised to `POPF`).  The raising instruction sets
a flag that skips exactly one boundary, for **every** recognition, and nothing
re-tests IE afterwards.  **This is what the ucore implements today** and it is
a genuine rival, not a straw man.

### §4.1 THE AUTHORISING OUTCOME

**S1 through S8 ALL met exactly as written above.**  Then, and only then, the
landing of §5 is taken.

### §4.2 THE REFUTING OUTCOMES

* **S1 or S2 ≥ 1** — the raising instruction's own boundary IS available to a
  maskable recognition.  The IE reading is REFUTED; *three* refuted arms is a
  finding about the question and it is booked as one.  **Nothing is landed.**
* **S3 or S4 ≥ 1** — silicon does NOT re-test IE at the deferred boundary; the
  mechanism is an opcode-set inhibit, not the IE level.  **Nothing is landed**,
  and INHIBIT is written up as the surviving reading.
* **S7 = 0 or S8 < 20** — the NMI is shadowed too, so the mechanism is not
  IE-gating.  **Nothing is landed** (this is §71.4's refutation reproduced on a
  directed cell, and it would make the five NMI bank seeds an artefact).
* **S5 < 24** or **S6 = 0** — the cell's own controls failed; the cell is
  INCONCLUSIVE and nothing is landed regardless of S1-S4.
