`v30sim timed-run` keys its record stream by the **array position** of the case
it was handed (`sim/timed_runner.cpp` 658-662: `long idx = 0; … run_one(…, idx,

*This is the instrument that produced §78.I's model column.*  Fixed in
`sw/sm3_haltsupp.py` and mirrored into the new `--core sim` leg of

## §2 LANDING A — THE MODEL'S LEG OF F54

### §2.1 THE MECHANISM, DERIVED BEFORE THE CODE IS TOUCHED

The model already renders the law in its own idiom.  `sim/timed_runner.cpp`
`run_evt`, the halted branch:

* the HALT announcement is a **queued write** to the display register
  (`biu_timed.cpp` 329: `halt_pending_ && !run_ && !cmt_valid_ && c != no_eval_`)
  — M20's sentence, *the wake and the HLT row write the same register and the
  wake can get there first*;
* `unhalt()` (`biu_timed.h` 236) clears `halt_pending_`, i.e. **cancels the
  queued announcement**, and the caller has already charged the BIU to the
  release clock, so the release clock IS the cancellation threshold;
* the INT arms release at **`a + 3`** — masked (`HLT.RES`) and vectored
  (`HLT.INT`) alike — which is `A + K` with **`K = 3`**, F54's INT constant, and
  the corrected instrument scores it EXACT on 1,008 cells;
* the NMI arm releases at **`a + 7`**, which is `A + 7`, i.e. **`K = 7`** — one
  clock later than F54's `K = 6`.

The ucore's F54 puts the same two integers on the display path only
(`eu_unhalt_disp`), leaving the EU's own unhalt sequencing (`unhalt_pend`, at
`c0 + 3 = A + 7`) where it was.  **The model's leg is written the same way**: a
display-only cancel at `A + 6`, leaving the model's `A + 7` wake schedule — the
entry clock, the prefetch restart, `cpu.interrupt()` — untouched.

### §2.2 THE CHANGE (one method, one call site)

```cpp
// biu_timed.h -- the ucore's `eu_unhalt_disp` in the model's idiom
void cancel_halt_disp() { halt_pending_ = false; }
```

```cpp
// timed_runner.cpp, run_evt, the halted branch, the NMI arm
if (rp.nmi) {
    biu.charge_to(a + 6);      // F54: A + K, K = 6 on the NMI pin
    biu.cancel_halt_disp();    // the ANNOUNCEMENT only; halted_ is untouched
    biu.charge_to(a + 7);      // B = a+5, entry at B+2 -- UNCHANGED
}
```

No constant is added that F54 does not already name, no per-delay table, no
per-program case, no new state.  `halted_` — the prefetch park — is deliberately
NOT cleared early: that is a different mechanism (family B) and folding it in
here would be the fitting this campaign forbids.

## §3 LANDING B — FAMILY B, THE ONE-CLOCK-LATE ANNOUNCEMENT

### §3.1 WHAT IS MEASURED (before any change), AND IT IS TWO SIGNATURES

At **w0 only**, in **both engines identically**:

| cells | first divergence | what the golden says |
|---|---|---|
| `HLT.INT` d2 · `HLT.RES` d2,d3 (S16: 10; sweeps: 3) | `(4, busstat) CODE -> PASV` | the wake's FIRST PREFETCH announcement is one clock late — and at `d2` that one clock puts it past the acknowledge's own slot, so the fetch is **LOST** |
| `HLT.INT` d3,d4,d5 (S16: 16; sweeps: 3) | `(4, busstat)` at d3, `(17, busstat) INTA -> PASV` at d4/d5 | at d3 the same late prefetch; at d4/d5 the **SECOND ACKNOWLEDGE** is one row late |

Measured on the goldens alone, `w0 p0 HLT.INT`, announcement rows:

* the first INTA's announcement is always the wake CODE announcement **+ 4**,
  in silicon and in the model, at every delay — that spacing is not in question;
* at `d5` the golden announces INTA1 at row 10 and INTA2 at row **17**; at `d6`
  it announces them at 11 and **18**.  **Announcement to announcement is 7
  clocks in both.**  The model gives 10 → 18 at `d5` (8) and 11 → 18 at `d6`
  (7): its second acknowledge is scheduled from the first cycle's COMPLETION,
  silicon's from the first cycle's ANNOUNCEMENT;
* in the cancelled regime the golden's whole post-wake schedule is a function of
  `H` and not of `A` — `d2` and `d3` produce **byte-identical captures** — and
  the wake's prefetch announcement sits at `H + 1` at w0 (`d2,d3 -> 4`, `H = 3`)
  and at `H + 1` at w1 (`d4..d7 -> 6`, `H = 5`), while the group of delays whose
  wake beat the park announces at `H − 1`.
