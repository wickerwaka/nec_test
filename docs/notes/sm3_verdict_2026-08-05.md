## (b) THE RIG — EVERY DEFECT FOUND, AND ITS CLOSURE EVIDENCE

The directive's second clause is about the rig, and this is the phase's largest
single body of work.  **Eleven distinct rig or instrument defects were found;
every one is fixed or explicitly routed, and each closure is a measurement.**

### (b.1) F46 / INV-1 — the 8-bit `evt_hold`.  **CLOSED BY RE-CAPTURE.**

*The defect*: `hps_axi_slave.sv` stored the pin-event hold in an **8-bit**
register, so a banked hold of 300 reached the socket as `300 & 0xFF` = **44**.
The truncation was silent.  The captures are TRUE SILICON; the **label** is
false, and therefore so is the directive an engine is handed
(`invalidation_ledger.md` §WHY).

*The fix, and the root cause is not the width*: 12 bits packed
`{wdata[30:27], wdata[23:16]}` into `EVT_CFG (0x20)`'s only free space, the wire
through `nec_bus.sv`/`system_large.sv`, `RIG_EVT_HOLD_BITS = 12` in one place,
and **`set_event` now RAISES on an out-of-range hold instead of truncating** —
*"the rig silently applied a directive other than the one it was handed"* is the
root cause, and the raise is the part that prevents the next F46 (§58.3).

*The closure evidence* (§59.7.3-§59.7.7, ledger §CLOSURE):

| | |
|---|---|
| the register | `EVT_CFG` **8/8 round-trip**, including 256, 300 and 4,095; `hold = 300` packs to `0x882C0000`, whose `[23:16] = 0x2C = 44` is the exact value F46 truncated to |
| **the pin** | one seed, one image, five directives differing only in `hold`, INTA T1 rows counted: **2 at 44, 6 at 300, 12 at 600**, against **2** in the seed's old banked capture |
| the re-capture | **760 new, 0 errors, 0 GEN-DRIFT, `evt_fired` 760/760** |
| the archive | **760 byte-identical copies** with `SHA256SUMS` `6f79283222d1…`, deliberately OUTSIDE `tests/v30/fuzz_bank/` so `check_fuzz_bank`'s corpus did not silently grow |
| the exclusion | **DERIVED, not listed and not renamed** — `timed_fuzz.f46_invalidated`.  Limb **(b)**, the APPLICATION test, was added after a Codex review found the predicate implemented only the one defect we had found (§64.3), and Codex's own equivalence test (`--rig-hold banked` vs `applied`, byte-identical reports) proves no current record is mis-applied |
| the bars | **ALL FOUR MET**; `timed_fuzz`'s `INVALIDATED` line is **0** on both engines and the gate is UN-SUSPENDED |

*What this says about the directive's own mechanics*: the directive prescribes
**archive by rename**.  That mechanism assumes the invalid artifact is a
DIRECTORY; here it was **a selection inside a shared directory**, and a rename
cannot express it.  A derivation from the record is strictly stronger, and it
self-heals on re-capture — which it did.

**INV-1 is the project's ONLY invalidation.**  The SM1 sweep audited and
**CLEARED** every other candidate — all `tests/v30` golden suites (the emitter's
max declared hold is 6), the four `evt` cells and `w1evt-biased`, the four HLT
sweeps, the b2/b3/b4 tranches, the sticky-divider era, the composed-AD mask, R6,
and the campaign logs — each with the evidence that clears it
(`invalidation_ledger.md` §AUDITED AND NOT INVALIDATED).  **INV-2 was considered
and NOT written** (§81.B.6): H7's floor did not reproduce, but the registered
outcome was (iv) — *report, do not fold* — and **nothing in the bank was
touched**.

### (b.2) The TB `IOW` store — a replay instrument, not an engine

`tb_v30_core.sv` gated its memory commit on `lat_write`, and `3'b010` is `IOW`,
so **an I/O write stored into `mem[]`** (§66.3).  The socket harness does not do
this, which is exactly how it was found: the chip reads the seed's own image at
an address the RTL legs read the I/O datum from.

*Closure*: one term (`lat_memw`).  **P1 met at its point estimate, 7/7** — the
seven REGISTERED seeds named in advance are cycle-exact — **9 improved, 0
worsened**; every golden that reaches `IOW` (the 23 `v0.3` block-I/O forms) is
unmoved at 229,999/229,999 (§67.1).  **Seven of the nine seeds `gaps` §T.2 called
"the ucore's OWN registered-bank residue" were the instrument's.**  The
`sig_ledger` admission that followed got its **own new control** rather than a
weakened one: `sw/sm3_iowpop.py` derives the population from the CHIP ROWS ALONE
(47 seeds), and all 5 improved and all 3 new-signature seeds are inside it and 0
outside (§68.8).

### (b.3) The composer — a comparator that asserted a mechanism

`tb_v30_core.sv`'s composer INFERRED the core's drive from the bus protocol, and
one term (`cycle_live`'s `lat_type != 3'b011`) floated a HALT-typed cycle's body
**whatever the core did there** — which is why the default TB scored F55's 35
cells green for eleven sittings **on the instrument's authority, not the core's**
(§81.A.3).  It is `standing_gates.md` meta-finding #5 one law later, and this
time caught by prediction.

*Closure*: the composer now keys on **`AD_OE`**, the core's own pad output
enable, a port added at §69 by explicit user decision (*"Okay, add the output
enable"*) and published by BOTH cores so the A/B discipline holds.  **Two lines
replaced eight wires, and it was landed ONLY on a zero-delta**: sweeps 273/283
cell for cell, S16 1,321/1,371 with 0 differing coordinates, `check_core`
169,000/169,000 and the whole ladder.  *Falsifier for the layer itself*: any cell
where `tb_v30_core` and `tb_sys` disagree again is a FINDING, not a tolerance.

### (b.5) The Quartus gate, and the A&S non-repeatability finding

*The absence*: sitting 11 landed RTL and ran no synthesis, which was ALLOWED
because no gate demanded one, and the DEFAULT build was later measured at
**19.42 MHz with 20,000 failing paths.  G6 was RED at HEAD and nothing in the
tree saw it** (§73.1) — the vacuous-gate pattern by ABSENCE.

*The fix*: `sw/quartus_gate.py` (§74.4), triggered on any commit touching the
ucore RTL, the shared integration, either `.qsf`, the SDC or the generated
tables; bars E1-E5 only (0 errors, `divclk` Fmax ≥ 32 MHz, worst setup > 0, TNS
0.000 setup AND hold); resources RECORDED and never barred; receipt to the
artifact layer's schema over an 88-file manifest.

*Its first act was to refute its own registered prediction.*  **Q2 is a
REGISTERED FAILURE**: the gate was registered to go RED on a worktree of
`144e67416b` reproducing 19.42 MHz, and it came back **45.91 MHz / PASS**.
Non-vacuity was proved instead on the **PRESERVED 19.42 MHz report set**, where
the gate exits 1 and goes RED at E3, E4 and E5 — the state it was built to catch,
proved on a historical artifact rather than by fishing for a re-draw.

*And Q2 found the real thing* (§74.4, §74.4a).  Four CONTROL builds of two trees
differing in one file draw **19.42 / 45.91 / 45.89 / 43.59 MHz**.  **The DEFAULT
build's Fmax is not a function of the RTL alone.**  Measured cause: `.qsf`
materialisation is **REFUTED** (a third build with the materialised `.qsf`
restored byte for byte reproduces 45.91 to the digit), and **Analysis & Synthesis
itself is not reproducible run to run** — the REGISTER counts are identical in
all four (`v30u_eu` 675, `v30u_biu` 402, `v30_core` 1077, which is §73.6's "no
flop moved" reproduced across a further sitting) while the COMBINATIONAL counts
differ between every pair, **including two builds of the same commit from a
deleted `db`**.  Two simple systems: a synthesiser that does not repeat itself
and a path that is marginal.

**Consequences booked, not smoothed**: §73's R7′ before/after may NOT be quoted
as "19.42 → 45.89" — what is not retracted is the STRUCTURAL result, the
`c_ready_q` cone from **62-63 logic levels to 19** with 0 failing paths and zero
ladder delta; and **every timing figure in this ledger from §52 onward is one
sample of a distribution nobody has characterised.**  The multi-seed form of the
gate is NOT built.
