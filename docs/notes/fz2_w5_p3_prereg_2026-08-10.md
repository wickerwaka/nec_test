## 0. WHAT WAVE-4 ESTABLISHED, AND WHY THIS IS A DIFFERENT CARRIER

Wave-4 (`fz2_w4_results_2026-08-10.md` §3) REVERTED package C.  Its two dead
ends, not to be rediscovered:

* routing the trap case into the BIU's **`halted`** — the PERMANENT park, one
  release (`eu_unhalt` via `S_HALTED`) — made the seats 440× worse;
* the naive **`if (eu_halt_susp) suspended = 1'b1;`** at the HLT DECODE fires on
  an ordinary `HLT` and, because `eu_unhalt` does not clear `suspended`, breaks
  `HLT.RES` (masked-INT wake, no flush).  `s10-hltsweep-w0`'s `HLT.RES` 49/49 is
  that form's falsifier.

## 1. THE MECHANISM, AS MEASURED (not as booked)

Direct `+utrace` on `fz2c/404071` (base `tb_sys`) shows the failing pattern is
**a code prefetch granted at the HALT WAKE, one to three clocks before the INTA
microcode's own `I_SUSP` (`eu_susp`) raises `suspended`.**  On the capture the
chip goes `fetch → one idle → INTA T1`; the core drives an EXTRA `ps=CODE`
fetch cycle first and reaches its INTA ~8 rows late.  The escaping fetch is
granted while `suspended = 0`; `eu_susp` from the vector microcode sets
`suspended` too late to withdraw it.

`eu_halt` (the park) and the recognition boundary (`eu_bnd_take`) are ~11 clocks
apart on this seed — the HLT PARKS and later WAKES — so the wave-task's
"coincident trap at the HLT retire" reading is **refuted by measurement**: the
carrier is the WAKE, not the retire.

**The distinguisher between a wake that must suspend and one that must not is
whether the wake VECTORS**, and that is the IE-gated recognition the EU already
computes:

* `HLT.INT` / the 3 C2 seats: pin high, IE set → `irq_int_lvl` true at the wake
  → the wake vectors (INTA), and the vector's `q_flush` RELEASES `suspended`.
* `HLT.RES`: pin high, IE clear → `irq_int_lvl` FALSE → the wake resumes the
  stream, and the resume prefetch is CORRECT and must not be suppressed.
* `HLT.NMI`: `hlt_wake_int` excludes NMI (`!irq_nmi_lvl`), so this term is inert
  on it — untouched by construction.

## 3. THE LAW (C-γ)

ONE predicate, no flop, no opcode named.  In `v30u_eu.sv`:

```
wire eu_halt_wake_susp = hlt_wake_int && irq_int_lvl;   // the vectoring wake
```

carried to the BIU's EXISTING prefetch-suspend on the EXISTING `eu_susp` port
(which already sets `suspended` at `v30u_biu.sv`'s first suspend site, ahead of
the grant eval) — i.e. the vector entry's suspend is made to START at the wake
decision rather than at the INTA row it currently rides:

```
assign eu_susp = (st == S_RESET) ||
                 (row_acts_ok && (e_type == TY_CTL) && !e_farjmp &&
                  (e_ictl == I_SUSP)) ||
                 eu_halt_wake_susp;                       // wave-5 P3 C-γ
```

`suspended` is RELEASED by `q_flush` (the vector redirect) exactly as today; the
masked `HLT.RES` wake never sets it (`irq_int_lvl` false), so the "no flush to
release it" failure mode cannot arise.

## 5. ss EXPECTATION

The term is combinational off existing signals (`hlt_wake_int`, `irq_int_lvl`);
**no flop is added, so `SS_VERSION`/`SS_COUNT`/`SS_TAG` DO NOT MOVE** and the
next free addr `9'h17E` is NOT consumed.  If implementation forces a flop, this
prereg is amended with the bump BEFORE the build.

## 6. FALSIFIER FOR THE LAW ITSELF

A capture in which the chip issues a code prefetch between a vectoring `HLT`
wake and that wake's own INTA/vector read (i.e. the chip prefetches where this
law suppresses), or a `HLT.RES` masked wake in which the chip does NOT prefetch
on resume (i.e. the law should have suppressed and did not).

## 7. STOP CONDITION

If the law closes fewer than the 3 seats, OR breaks any G-5/G-6/G-7 falsifier,
OR the only way to protect `HLT.RES` is a second case (`... && !something`),
then the mechanism is not the die's one prefetch-suspend and this is REVERTED
and BOOKED, not fitted around.
